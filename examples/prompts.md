# Example prompts

Prompts that exercise the skill. Scope the run to the request: expressive briefs need
a functional flagship prototype and independent browser review before surrounding-page
construction; composed pages and serious app screens remain task-first. Review and
component requests do not authorize unrelated page rebuilding.

## Pages

- "Build a landing page for a bakery that only opens at dawn."
- "Redesign this page, it looks generic."
- "Animate this hero."
- "Make a portfolio for a photographer who shoots only at night."
- "Build a product page for a single chair with useful 3D inspection. Check whether
  the required model/views are available; prototype the inspection first."

## App screens

- "Design a settings screen for a billing tool; dense but calm."
- "Build an inbox view with a command palette."
- "Design a serious order-management screen. Use consistent tables, native navigation
  and brief state feedback; do not force a cinematic showpiece."

## Components

- "Add a scroll-pinned scene to this section that explains the repair process."
- "Make this button magnetic and add a character-reveal headline."

## Creative animation

- "Build a shinobi scroll-driven site: a long take through a single fight, with
  real/authored character artwork, readable illustrated close-ups and chapter navigation.
  Prototype the functional flagship first. If the required assets are missing, ask
  or offer an honest feasibility prototype; do not substitute character rectangles."
- "Build an Itachi-themed page: the Sharingan as the live thing (a viewer that
  changes what is visible), scroll scenes carrying the ritual of the fight."
- "Build an expressive computer store around an exploded compatible workstation.
  Choosing a workload must expose useful parts relationships and honest workload
  evidence, then resolve into a selectable build. Prototype and independently review
  its actual desktop/phone recording before surrounding-page construction."
- "Design a spatial computer-store workbench: category selection -> item inspection
  -> configuration/cart, with native DOM fallback. Preserve one connected useful
  journey rather than padding a motion inventory."
- "Make a camera product stage whose physical turn exposes controls and specs.
  Match asset fidelity to the promise; do not call a flat tilt photorealistic 3D."
- "Translate a user-described logistics globe -> crane -> container -> truck side/top
  -> ship pullback into a connected service journey. Do not claim its source mechanism
  was verified without a supplied recording."
- "Prototype a lab scene with a deforming iridescent mesh and cylindrical type tied
  to a meaningful parameter. If promising true glass, show pixel refraction and
  chromatic aberration, not blur. Keep semantic controls and static alternatives."

See [reference-translations.md](../references/reference-translations.md) for optional
camera/material/spatial grammar and asset requirements. No minimum scene, motion,
entity or property count and no mandate to use all four paradigms.

## Review

- "Run the gate on this page and tell me the top three problems."
- "Audit this site against tells.md and fix the worst three."
- "Review this flagship from its actual desktop and phone recordings. Cite current
  artifacts and distinguish evidence completeness from independent creative acceptance."
- "Reject this proposed cinematic result if its only action is a product card scaling
  5% and tilting 4 degrees across five named phases. Do not replace that criticism
  with a larger-angle/percentage rule."
- "The third visual iteration still misses the promised scene. Report rejected or
  blocked, cite the recording and ask for the asset/scope decision; do not accept
  the remaining failures as taste."
